# Six-direction benchmark contract

This contract extends the three-direction customer proof contract for internal creative benchmarking. It does not change production package pricing or authorize customer delivery.

Each project must produce exactly six responsive, working website directions:

- one restrained direction at FAMtastic level 0-3;
- one medium direction at FAMtastic level 4-7;
- four ultra directions at FAMtastic level 8-10.

Every direction must have a distinct information architecture, distinct primary artwork, customer-specific copy, a desktop screenshot, a mobile screenshot, and browser QA with no horizontal overflow, missing image, missing alt text, console error, page error, or failed request.

Typography is part of the concept rather than a final decoration. Every
direction must use a named display composition beyond generic bold, color, or
italic treatment. Every direction must also apply a business-specific pattern,
texture, material, or surface-depth system to backgrounds or containers. Safe,
original transformations of subject-native symbols are encouraged. An official
mark, mascot, person, or affiliation may not be copied or implied without
authority.

Reuse of tested grids, components, interactions, and responsive patterns is
allowed when the new direction receives its own research, thesis, copy, assets,
visual grammar, and QA. Wholesale copying of a previous site is not allowed.

The package must contain a manifest, research record, build brief, agent ledger, prompt ledger, technical QA, independent visual review, SHA-256 integrity ledger, and a review room. Claims about model diversity must name the actual providers and models used.

All outputs are retained. Unselected work remains internal-only by default. Reuse is limited to de-identified structure and design rationale until an owner reviews rights. Customer copy, customer uploads, customer identity, and customer-specific artwork are never silently converted into templates or public portfolio pieces.

A batch passes only when every project has a unique request ID, the expected account identity is preserved, every project passes the exact direction mix, all direction HTML hashes are unique, all required screenshots exist, and all technical and visual gates pass. The visual gate rejects subject-agnostic concepts, recolored templates, flat untextured surfaces, generic display type, poster-only pages, weak conversion, and inaccessible mobile behavior. Fixture or synthetic runs are classified as locally proven, never production proven.

Speed is governed by bounded review, not by weakening the gate. The default
preview budget is one initial independent review, one consolidated repair, and
one post-repair review only when rendered artifact hashes changed. Unchanged
work reuses its recorded verdict. Research, generation-to-QA, and
selected-direction refinement are recorded as separate clocks. Noncritical
polish moves to the selected direction rather than being multiplied across all
six preview candidates.
