# Omar Top Deals flyer storefront v2

## Purpose

Create a separate public Version 2 that translates the visual energy of Omar's current flyer into a functional, mobile-first merchandise storefront without replacing the live Version 1.

## Creative direction

- Preserve the flyer's strongest portable patterns: sunset heat, dense collage, culture-forward color, high-contrast deal labels, small schedule-like facts, and layered paper edges.
- Use Omar's real owner-supplied merchandise photographs as product proof. Native HTML owns every headline, product name, price, disclosure, and control.
- Make the page feel like a digital handbill: dramatic hero, four demo deal cards, one value bundle, market-day path, mentor story, and owner-prototype continuation.
- Keep every price visibly labeled as a demo recommendation until Omar confirms it. No inventory, scarcity, discount, sale, payment, shipping, order, or hold is represented as live.

## Product-value hypotheses for Omar review

| Product family | Demo value shown | Boundary |
| --- | --- | --- |
| Statement bucket hats | $25 each / 2 for $40 | Recommendation only; Omar confirms inventory and price. |
| Fraternity and team finds | From $25 | Recommendation only; sizes, teams, licensing, and availability are unverified. |
| United States of Africa tees | $30 | Recommendation only; sizes and inventory are unverified. |
| Culture and home finds | From $20 | Recommendation only; exact assortment and value are unverified. |

## Component recipe

`nav -> flyer-hero -> value-strip -> deal-wall -> market-story -> market-day-path -> mentor-note -> next-pop-up/contact`

Version 2 is a materially different page recipe, not an image swap. It reuses the same owner-console continuation and browser-local demonstration boundary.

## Success gates

- Distinct from Version 1 and clearly derived from the current flyer.
- Four product/value cards using owner-supplied product evidence.
- All pricing labeled as demo recommendations.
- Native readable text, keyboard controls, reduced-motion fallback, and no 390px horizontal overflow.
- Hold interaction persists into the existing owner prototype on the same device.
- No application API, payment, email, social, inventory, or external communication effect.
- Production build and real-browser verification before public handoff.
