# FAMtastic Designs production SEO audit

Audit date: 2026-08-11  
Production origin: `https://famtasticdesigns.com/`  
Overall SEO readiness score: **64/100**

This is a repeatable, evidence-based readiness score, not a Google ranking or
an estimate of Google's private algorithms. Google Search Console remains the
authority for indexing, queries, impressions, clicks, and page-level issues.

## Executive finding

The site has a strong crawl foundation and a much larger, internally linked
content footprint than it had before: HTTPS, robots discovery, 85 canonical
sitemap URLs, 64 published articles, clean public URLs, responsive layouts,
and route-specific metadata. The main constraint is no longer a missing
sitemap. It is the React app-shell architecture: most initial HTML responses
contain metadata but zero primary-content words, zero H1s, and no structured
data. Google can render JavaScript, but pre-rendering the important content is
faster, more reliable for crawlers, and better for customers.

Sampled public search-result queries did not surface the domain during this
audit. That is not proof that nothing is indexed; confirm exact coverage in
Google Search Console.

## Confirmed strengths

- `robots.txt` is valid for public discovery and points to the root sitemap.
- Sitemap XML is valid and contains 85 unique HTTPS URLs.
- All 85 sitemap URLs returned HTTP 200 during the audit.
- The sitemap contains no HTTP URLs or duplicates.
- HTTP redirects to HTTPS with one 301.
- `www` pages declare the non-`www` canonical origin.
- Core public routes have unique title/description shells except the About gap.
- The rendered homepage has one H1 and about 528 main-content words.
- A sampled article rendered one H1, about 1,192 main-content words, an image
  alternative, internal links, and Article/Breadcrumb JSON-LD.
- Mobile layouts tested without horizontal overflow.
- Lighthouse 13.4.1 scored SEO 100, Accessibility 96, and Best Practices 100;
  that checklist score is narrower than this full audit.

## Launch-priority findings

### P0 — Fix canonical and metadata coverage

- `/about/` currently sends the homepage title, description, and canonical in
  both raw and rendered HTML. Add About to the canonical SEO route registry.
- Audit every sitemap URL for unique title, description, canonical, and one H1.
- Keep the same canonical in the server shell and rendered DOM.

### P0 — Put primary content in initial HTML

- Pre-render or server-render homepage, service, package, About, Contact, blog
  index, and article content—not only their metadata shells.
- Emit Article, Breadcrumb, Organization, WebSite, Service, Product/Offer, and
  appropriate page schema in initial HTML where truthful.
- Ensure unknown routes return real 404 status codes rather than a 200 SPA shell.

### P1 — Repair mobile performance

- Mobile Lighthouse performance is 62 with an 8.4-second LCP.
- Split the 543 KB JavaScript bundle by route; Lighthouse estimates roughly
  374 KB of unused JavaScript on the homepage.
- Add effective long-lived caching for fingerprinted assets; Lighthouse
  estimated about 530 KB of cache-lifetime opportunity.
- Reduce render-blocking work (estimated 1.26 seconds), self-host/subset critical
  fonts where useful, and prioritize the true LCP asset.
- Measure real 75th-percentile LCP, INP, and CLS through Search Console/CrUX
  after traffic becomes available.

### P1 — Establish entity, authorship, and trust

- Add Organization + WebSite schema on the homepage with a stable `@id`, logo,
  contact point, and verified sameAs profiles.
- Add Fritz Medine as a real author/reviewer entity with a biography, relevant
  experience, and a linked author page.
- Add truthful editorial/process disclosure explaining human review and how
  automation or AI assisted the content library.
- Upgrade key articles with screenshots, implementation evidence, named
  examples, measured outcomes, and original FAMtastic lessons.
- Avoid relying on 64 structurally similar articles alone; Google explicitly
  favors original, helpful, people-first value over scaled search-first output.

### P1 — Submit and measure discovery

- Verify the exact domain property in Google Search Console.
- Submit `https://famtasticdesigns.com/sitemap.xml` and inspect homepage,
  About, services, packages, and representative articles.
- Record indexed/not-indexed counts, crawl dates, impressions, queries, CTR,
  and rich-result issues in the Drupal analytics/SEO command center.
- Add Bing Webmaster Tools and implement a real IndexNow key/endpoint if Bing
  freshness is a priority.

### P2 — Build local authority deliberately

- Decide whether the supplied address is customer-facing or mail-only before
  publishing it as LocalBusiness data.
- If FAMtastic is a service-area business, use Organization/ProfessionalService
  identity plus truthful `areaServed`; do not imply that customers can visit a
  mailbox location.
- Add a verified phone number, business hours/availability, and consistent NAP
  only after the public-contact policy is decided.
- Create one genuinely local Port Saint Lucie/Treasure Coast service page with
  unique experience—not mass-produced city swaps.
- Claim/complete Google Business Profile, Bing Places, Apple Business Connect,
  and relevant citations; establish an ethical review-request process without
  review gating.

### P2 — Sitemap and image discovery refinements

- Add accurate `<lastmod>` dates based on meaningful content changes.
- Consider image sitemap entries for the branded article visuals.
- Keep the current canonical-only, HTTPS-only URL set.

### P3 — Defense in depth

- Add HSTS after confirming all required subdomains are HTTPS-ready.
- Add a tested Content-Security-Policy, Referrer-Policy, Permissions-Policy,
  X-Content-Type-Options, and suitable framing policy without breaking Drupal,
  Stripe, analytics, fonts, or portal flows.
- Make `/llms.txt` a real text file only if it contains useful, maintained
  guidance; it is not required for Google SEO.

## Evidence and limitations

- Lighthouse 13.4.1 mobile-default and desktop lab runs were captured from the
  production homepage. Lab measurements vary and are not field Core Web Vitals.
- The public PageSpeed API was quota-blocked; Lighthouse was run directly.
- Search-result sampling is not exhaustive. Search Console URL Inspection is
  required to confirm Google index status.
- This audit did not have authenticated Search Console, GBP Insights, backlink
  index, review platform, or geo-grid ranking data.
- Local score is intentionally conservative because visible NAP, GBP, reviews,
  and LocalBusiness schema could not be verified.

## Recommended completion order

1. Fix About and run the canonical/meta/H1 audit across all 85 URLs.
2. Pre-render critical page content and schema; implement real 404 responses.
3. Reduce mobile LCP and route-split JavaScript.
4. Add truthful Organization/author/editorial identity.
5. Submit and inspect the sitemap in Search Console.
6. Decide service-area/NAP policy, then build local identity and citations.
7. Add evidence-rich case studies and progressively upgrade the strongest blog
   clusters using Search Console demand data.
