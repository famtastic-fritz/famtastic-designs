## 1. Order #15 / "FAMtastic by the Numbers" — PRODUCT MISMATCH

### Finding
Order #15 (Commerce entity ID 15, order number 2) was a **Web Basics Bundle (FAM-FOOT-199, $199)** purchased through Drupal Commerce checkout (`/web/checkout/15/*`). The FAMFOUNDER coupon reduced it to $1.00.

**"FAMtastic by the Numbers" is NOT in the Commerce product catalog.** It is a separate app located at `~/Development/FAMtastic/Apps/famtastic-by-the-numbers` with its own Netlify deployment. It is listed in `SYSTEMS.md` as a standalone product — it was never wired into the Drupal Commerce catalog.

### What the user expected vs. what happened
- **Expected:** Purchase "FAMtastic by the Numbers" and see it in the portal
- **Actual:** Purchased a website bundle (FAM-FOOT-199) because that was the product available in Commerce

### Root cause
The Commerce catalog (`backend/config/famtastic-products.json`) only contains website-related SKUs. There is no SKU for "FAMtastic by the Numbers" and no entitlement type for it.

### Fix options (pick one)
| Option | Effort | Description |
|--------|--------|-------------|
| A. Add to catalog | Medium | Create a new SKU (e.g., `FAM-NUMBERS-99`) in `famtastic-products.json`, add entitlement type `by_the_numbers`, wire fulfillment to provision access |
| B. Remove from storefront | Low | If "by the Numbers" is not ready for sale, ensure it does not appear in any Commerce product listings or marketing copy |
| C. Separate checkout | Medium | Keep "by the Numbers" as a standalone app purchase with its own Stripe/payment flow, and only link the website bundles through Drupal Commerce |

**Recommended:** Option A if you want to sell it; Option B if it's not ready yet.

### 2.4 Services (`section === 'services'`) — ⚠️ ISSUES FOUND
**File:** `frontend/src/pages/CustomerPortalDashboard.jsx` lines 110-130

| Element | Current Link | Should Be | Severity |
|---------|-------------|-----------|----------|
| "Manage" button on owned services | `go('projects')` or `go('messages')` | ✅ OK for now | Low |
| **"Explore →" on recommended modules** | **`/contact?service=${sku}`** | `/buy` or in-portal detail | **High** |

**Root cause:** `PortalServices` renders promoted catalog items with `<a href={`/contact?service=${encodeURIComponent(item.sku)}`}>Explore →</a>`. This dumps the user out of the portal to the public contact form.

**Fix:** Change the link to `/buy?sku=${item.sku}` (or a new portal-native product detail view). The `PurchasePage.jsx` already supports direct SKU selection via query params.

### 2.5 Growth Ideas (`section === 'grow'`) — ⚠️ ISSUES FOUND
**File:** `frontend/src/pages/CustomerPortalDashboard.jsx` lines ~360

| Element | Current Link | Should Be | Severity |
|---------|-------------|-----------|----------|
| Each growth offer card | **`/contact?service=${offer.key}`** | `/buy` or actionable in-portal | **High** |
| "Describe my goal" | `go('support')` | ✅ | Correct |

**Root cause:** `workspace.offers` (generated by `CustomerPortalService::contextualOffers()`) returns offers with keys like `analytics`, `seo`, `lead_automation`, `site_expansion`. The frontend blindly links all of them to `/contact?service=${offer.key}`.

**Fix:** Map offer keys to actual SKUs or portal actions:
- `analytics` → `/buy?sku=FAM-ANALYTICS`
- `seo` → `/buy?sku=FAM-LOCAL-SEO`
- `lead_automation` → `/buy?sku=FAM-LEAD-AUTOMATION`
- `site_expansion` → `/buy?sku=FAM-PAGE-EXTRA`
