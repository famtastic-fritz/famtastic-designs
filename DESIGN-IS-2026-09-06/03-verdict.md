# Verdict

The defect is information architecture, not merely visual polish. A client
should never have to interpret an internal proof status, decide whether a
technical domain field applies, or hunt through a command center to learn what
to do.

The replacement pattern is: **Projects list → one project → Today → Concepts →
Research & growth plan → Setup → More.** Each stage uses customer language,
shows only one primary action, and hides operator provenance. A revision hides
the rejected choice controls and says plainly that a new set is being made.

The reusable fix includes `design.md`, template versions, a customer-proof
rebuild audit path, transparent domain candidates, and a structured growth-plan
slot. A future clarification workflow must add a durable question record and a
focused email/portal answer step before it can claim automatic clarification.
